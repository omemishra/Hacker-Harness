# OAuth 2.0 & OIDC Authorization Assessment & Flow Abuse

## 1. Prerequisites & Input Contract
- **Authorization Scope:** Authorized target identity providers, client IDs, and authorization endpoints in `scope.yaml`.
- **Target Credentials:** Test victim account (Account A) and test attacker account (Account B) on the same identity provider.
- **Traffic Interception:** Route OAuth authorization code flows and token exchange requests through Caido proxy.

---

## 2. Core Attack Heuristics & Step-by-Step Flow

### Step 1: Authorization Endpoint Analysis & Parameter Tampering
Inspect the initial authorization URL generated by the client application:
```http
GET /authorize?response_type=code&client_id=client123&redirect_uri=https://app.example.com/callback&scope=openid%20profile%20email&state=xyz123 HTTP/1.1
Host: idp.example.com
```

### Step 2: `redirect_uri` Validation & Regex Bypasses
Test whether the identity provider permits unauthorized redirect destinations to leak the authorization code or access token:
1. **Directory Traversal / Path Bypasses:**
   * `https://app.example.com/callback/../../attacker-endpoint`
   * `https://app.example.com/callback?forward=https://attacker.com`
   * `https://app.example.com.attacker.com/callback`
2. **Subdomain / Parameter Confusion:**
   * `https://app.example.com/callback%23@attacker.com` (Fragment injection)
   * `https://app.example.com/callback%0d%0aLocation:https://attacker.com` (Header splitting)
   * `https://app.example.com:443@attacker.com` (Userinfo confusion)
3. **Open Redirect in Whitelisted Domain:** Chain with an open redirect on `app.example.com` to bounce the code:
   * `https://app.example.com/oauth/callback?next=https://attacker.com`

### Step 3: State Parameter Omission & OAuth Account Takeover (CSRF)
1. **Omit `state` Parameter:** If the client does not send or validate the `state` parameter upon `/callback`, capture an authorization code generated for Attacker Account B.
2. **Victim Code Injection:** Force a victim user to visit `https://app.example.com/callback?code=<ATTACKER_CODE>`.
3. **Verdict:** If the victim's session binds to the attacker's third-party identity, the attacker logs in via OAuth and gains access to victim resources (Account Takeover).

### Step 4: Scope Escalation & ID Token Forgery
1. **Scope Escalation:** Request elevated scopes (`scope=openid profile admin:write internal_tools:read`).
2. **Response Mode Manipulation:** Switch `response_mode=query` to `response_mode=fragment` or `response_mode=form_post` to inspect token delivery behavior.
3. **ID Token Claim Tampering:** Check if backend verifies the JWT signature or blindly trusts claims:
   * Change `"sub"` / `"email"` in the ID token and send to `/api/auth/token-login`.

## 3. Empirical Disclosed Report Patterns & High-Risk Matrices

| Attack Vector | Vulnerability Mechanism | Empirical Disclosed Pattern | Expected Evidence Marker |
|---|---|---|---|
| **Code Leak via Open Redirect** | Whitelisted callback has open redirect | `/authorize?redirect_uri=https://target.com/login?redirect=https://attacker.com` | Authorization code leaked in Referer or URL redirect |
| **Pre-Account Takeover (OAuth Linking)** | Platform merges OAuth without email verification | Register victim email via Google/GitHub OAuth on target platform | Attacker logs in without password; merges with victim profile |
| **Client Secret Leak in SPA/Mobile App** | Hardcoded client secret in frontend bundle | Grep JS bundle for `client_secret: "..."` | Full `/token` exchange enabled without server proxy |
| **PostMessage Token Interception** | Popup callback uses `postMessage(code, "*")` | Target window listens on `window.addEventListener("message", ...)` | Token stolen by malicious opener iframe |

---

## 4. Evidence Collection & Validation Gate
1. **Reproducible Flow:** Capture the exact request chain:
   - Initial `/authorize` request with tampered parameters.
   - IdP 302 redirect carrying the leaked code to the unauthorized destination.
   - Successful token exchange (`/token`) using the leaked authorization code.
2. **Impact Proof:** Demonstrate authenticated access to user profile or data using the stolen token.
3. **Remediation:** Enforce exact string matching for `redirect_uri`, require and cryptographically bind `state`/`PKCE` parameters, and verify ID token signatures against IdP JWKS.
